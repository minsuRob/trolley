# 화면이 바뀌었을 때의 확인 절차

`CLAUDE.md` 는 "띄워서 눈으로 본다" 까지만 적는다. 그 다음이 매번 즉흥이었다 — 어떤 때는
System Events 로 창을 뒤졌고, 어떤 때는 화면 전체를 찍어 놓고 우리 창이 어느 앱 뒤에 있는지
찾았다. 이 문서가 그 순서다. **화면이 바뀌는 변경을 확인할 때 먼저 읽는다.**

절차는 넷이고, 순서가 있다.

## 1. 빌드는 공증 없이

```sh
Scripts/dev-run.sh            # swift build → .build/dev/trolley.app → open -n
```

몇 초 걸린다. **확인에는 공증이 없다** — 공증은 Apple 왕복 8~10분이고 배포에만 필요하다.
권한(손쉬운 사용·화면 기록)이 걸린 것을 볼 때만 서명 빌드로 올라가는데, 그쪽도 공증은
건너뛴다:

```sh
Scripts/dev-run.sh --signed   # = build-installer.sh --skip-notarize, 몇 분
```

`/Applications/trolley.app` 은 건드리지 않는다. 끝나면 `pkill -f '.build/dev/trolley.app'`
로 dev 번들만 끈다.

## 2. 창은 trolley 자신이 연다

확인에 쓰는 것은 **trolley 자체의 computer use** 다. 자기 손으로 자기 창을 여는 것이고,
그 경로가 망가지면 확인하다가 먼저 알게 된다.

```sh
./.build/debug/trolley click --bundle-id ink.markhub.trolley --text "위키 열기"
```

- **메뉴 막대 항목은 이 길로 안 잡힌다**(실측). 상태 항목은 앱의 창 트리 밖에 있어서
  `click` 의 순회에 걸리지 않는다. 설정 창에 있는 버튼(`위키 열기` 등)을 쓴다.
- 글자가 여러 곳에 있으면 가장 안쪽 요소가 눌린다. `위키` 로 누르면 설정 창의 설명
  줄이 눌리고 아무 일도 일어나지 않는다 — 버튼의 제목을 그대로 적을 것.
- 글자 입력은 `type-text --bundle-id … --text …`, 값 넣기는 `setvalue` 다.

## 3. 무엇이 어디에 있는지는 `dump-tree --frames`

```sh
./.build/debug/trolley dump-tree --bundle-id ink.markhub.trolley --max-depth 6 --frames
```

```
AXSplitGroup | … | frame=504,187 912x383 | children=6
  AXScrollArea | … | frame=504,187 400x366 | children=1
    AXTable | … | frame=504,215 400x338 | children=4
      AXColumn | … | frame=505,216 194x336 | children=0
      AXColumn | … | frame=699,216 73x336 | children=0
      AXColumn | … | frame=772,216 126x336 | children=0
```

레이아웃 주장은 여기서 숫자로 확인한다 — 열 세 개의 합이 목록 폭 안에 있는가, 나눔선을
끌면 어느 쪽이 넓어지는가, 창을 좁히면 무엇이 먼저 줄어드는가. 눈으로만 보면 "잘려 보이는
것 같다" 에서 멈추고, 그 상태로 고치면 다음 화면 크기에서 같은 자리가 다시 잘린다.

## 4. 그림은 창 단위로 찍는다

```sh
Scripts/window-shot.swift 위키 /tmp/wiki.png
```

창 제목의 일부를 주면 그 창만 찍는다. **화면 전체나 좌표 영역으로 찍지 않는다** — 실측으로
두 번 틀렸다: 앞으로 꺼내는 데 실패해 다른 앱이 찍혔고, macOS 동의 창이 우리 창 위를 덮은
채로 찍혔다. `screencapture -l` 은 가려져 있어도 그 창의 버퍼를 가져온다.

## trolley 로 안 될 때: Claude 의 computer use

`click` 이 요소를 못 찾거나, 권한이 막혀 있거나, AX 트리에 아예 없는 것(메뉴 막대, 시스템
동의 창)을 눌러야 할 때만 `mcp__computer-use__*` 로 넘어간다. 사람의 허락을 한 번 받는
경로이므로, **위의 셋을 먼저 시도해 보고 그 실패를 근거로** 넘어간다. 넘어갔다는 사실은
보고에 적는다 — 자체 경로가 막혀 있다는 것 자체가 고칠 거리다.

## 확인하다가 사람의 것을 건드리게 되는 두 곳

**볼트.** dev 번들은 빌드마다 애드혹 서명의 cdhash 가 바뀌므로 `~/Desktop` 접근 허락을
물려받지 못한다. 목록에 실제 데이터가 필요하면 임시 볼트를 만들어 그쪽을 가리킨다:

```sh
mkdir -p /tmp/vault/context/tasks && cp <페이지 몇 개> /tmp/vault/context/tasks/
defaults write ink.markhub.trolley trolley.wiki.root -string /tmp/vault
# … 확인 …
defaults write ink.markhub.trolley trolley.wiki.root -string "$원래_경로"
```

**끝나면 반드시 원래 경로로 되돌린다.** 먼저 `defaults read ink.markhub.trolley
trolley.wiki.root` 로 적어 두고 시작할 것.

**UserDefaults.** dev 번들과 설치본은 identifier 가 같아 **같은 도메인**
(`ink.markhub.trolley`)을 쓴다. 확인하면서 만들어진 값 — 끌어 본 나눔선 폭, 열 폭 autosave
— 은 사람의 앱에 그대로 남는다. 확인이 끝나면 지운다:

```sh
defaults delete ink.markhub.trolley trolley.wiki.window.listWidth
defaults delete ink.markhub.trolley "NSTableView Columns v3 trolley.wiki.list"
```

지운 뒤 한 번 더 띄워, 처음 쓰는 사람이 보게 될 기본값을 눈으로 본다. 저장된 값이 남아
있는 화면은 "기본값이 괜찮다" 의 증거가 되지 못한다.
